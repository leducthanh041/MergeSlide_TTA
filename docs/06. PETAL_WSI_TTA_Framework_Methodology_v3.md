# Framework TTA cho WSI: Tích hợp PETAL + DaPC + NOTE + WSI Feature Augmentation

> **Phiên bản:** 3.0 — Loại bỏ $\mathcal{L}_{task}$, làm rõ attribution OOD score, thêm TCP confidence gate tại inference, đồng bộ toàn bộ ký hiệu toán học.
> **Bối cảnh:** Test-Time Adaptation (TTA) cho mô hình MergeSlide (TITAN-based) trên các tác vụ phân loại ung thư WSI đa site, gồm cả setting IND và OOD.

---

## 1. Bài toán và Động lực

### 1.1 Thiết lập bài toán

Cho mô hình `merge_final` — mô hình MergeSlide đã được huấn luyện tuần tự trên $T$ tasks, với tham số hợp nhất $\tilde{\theta}_{1:T}$. Tại inference, với mỗi task $t$ đến, mô hình phải thích ứng với một luồng WSI **không có nhãn** $\mathcal{U}^t = \{x_m^t\}_{m=1}^{M_t}$ trong điều kiện:

- **IND setting:** Tập test có site overlap cao với tập train (BRCA: 20.5, RCC: 30.3, NSCLC: 37.1). Tuy nhiên vẫn tồn tại một tỷ lệ nhỏ OOD samples.
- **OOD setting:** 100% mẫu test đến từ các site hoàn toàn mới (site overlap = 0). OOD validation rất nhỏ và bất ổn định (ESCA val min=1, TGCT val min=1).
- **Ràng buộc cứng:** Không có nhãn, không lưu dữ liệu cũ, không reset mô hình về scratch.

### 1.2 Kiến trúc MergeSlide — điểm khác biệt quan trọng so với natural image TTA

Mô hình MergeSlide thực tế gồm hai thành phần:

```
backbone = titan.vision_encoder     ← CẬP NHẬT tại TTA (LayerNorm params)
mlp      = Linear(768, n_classes)   ← FROZEN, init từ prompt prototypes
```

Forward pass cho một slide:

$$Z_i = \text{backbone}(\text{features},\, \text{coords},\, \text{ps}) \in \mathbb{R}^{768}$$

$$\text{logits} = \text{mlp}(Z_i) = Z_i \cdot W_{class}^\top + b \in \mathbb{R}^{n_{classes}}$$

trong đó $W_{class} \in \mathbb{R}^{n_{classes} \times 768}$ là **prompt prototype weights** — cột $j$ là embedding của class $j$ từ TITAN text encoder, frozen hoàn toàn. Điều này có nghĩa là $\text{logits}_j = Z_i \cdot e_j^\top$ — dot-product similarity với class embeddings, được implement qua `nn.Linear` frozen.

**Hệ quả cho TTA:** Gradient từ loss chỉ chảy qua `backbone` (vì `mlp` frozen). Mục tiêu của tất cả loss components là buộc `backbone` tạo ra slide embeddings $Z_i$ ngày càng align tốt hơn với frozen class prototypes trong điều kiện domain shift.

**Hệ quả với TCP Inference:** Khi backbone được cập nhật tại TTA, $Z_i$ dịch chuyển trong embedding space, có thể làm cho việc so sánh với task-level prompt embeddings $\mathcal{E}^T$ bị kém chính xác — đây là TCP routing degradation. Framework phải phòng ngừa hiện tượng này thông qua cơ chế confidence gate tại inference (xem Phase 7 trong thuật toán).

### 1.3 Các thách thức cần giải quyết đồng thời

| Thách thức | Nguồn gốc |
|---|---|
| Catastrophic forgetting | Cập nhật backbone làm mất tri thức từ $T$ tasks đã merge |
| Tích tụ lỗi (error accumulation) | Pseudo-labels nhiễu tích lũy theo thời gian |
| IND/OOD mixed stream | IND: có % nhỏ OOD; OOD: 100% mẫu OOD |
| Class imbalance | CESC, BRCA mất cân bằng mạnh; RCC lệch class 2 |
| OOD val cực nhỏ và bất ổn | ESCA val min=1, TGCT val min=1 → không thể tuning trên OOD val |
| Nhãn giả không tin cậy | Đặc biệt khi domain shift lớn (setting OOD hoàn toàn) |
| TCP routing degradation | Backbone drift làm Z_i không còn align tốt với task prompts |

## 2. Kiến trúc Tổng thể

Framework **MergeSlide-TTA** tích hợp 5 module theo sơ đồ:

```
WSI (features [N,768] + coords [N,2])
        │
        ▼
[Module A] WSI Bag-level Augmentation
   K lần subsample → K bag variations {B^(k)}
        │
        ├──────────────────────┐
        ▼                      ▼
   Student backbone        Teacher backbone (EMA)
   (cập nhật backprop)     (θ' = π·θ' + (1-π)·θ_s)
        │                      │
        │   [Module B] DaPC Pseudo-label Correction
        │   anchor confidence vs teacher → y_corrected
        │                      │
        └──────────┬────────────┘
                   ▼
   [Module C] Hàm Loss Tổng hợp
   L_total = L_PETAL + γ_class · L_class
                   │
                   ▼
   [Module D] FIM-based Parameter Restoration
   Reset params có F_p < quantile(F, δ) về θ_0
                   │
                   ▼
   [Module E] Adaptive Learning Rate (OOD-score based)
   η_eff = η_base · σ(OOD_score − τ_OOD)
                   │
                   ▼
   [Inference] TCP Confidence Gate
   Chỉ dùng TCP routing nếu conf(Z_teacher, E^T) ≥ τ_task
```

## 3. Chi tiết từng Module

### Module A: WSI Bag-level Augmentation

#### Vấn đề

PETAL gốc dùng $\tilde{y}' = \frac{1}{K}\sum_{i=1}^K p(y|\alpha_i(\bar{x}), \theta')$ với $\alpha_i$ là pixel augmentation (xoay, flip, crop). Với WSI, input tại TTA time là bag embeddings đã được pre-extracted và frozen — pixel augmentation không áp dụng được.

#### Giải pháp: WSI Feature Augmentation (từ Frozen-to-Paraffin)

Augment ở **cấp phân phối đặc trưng túi** bằng patch subsampling ngẫu nhiên:

$$B_i^{(k)} = \text{RandomSample}(B_i,\; r_{patch} \cdot |B_i|), \quad k = 1, \ldots, K$$

với $r_{patch} \in \{0.50,\, 0.75\}$. Augmentation-averaged teacher prediction:

$$\tilde{y}' = \frac{1}{K} \sum_{k=1}^{K} \text{softmax}\!\left(\text{mlp}\!\left(\text{backbone}(B_i^{(k)}, \theta')\right)\right)$$

**Lý do hiệu quả:** Phân bố bệnh học không đồng đều trên WSI (patchy distribution) — mỗi subsample nhấn mạnh vùng mô khác nhau, tạo ra $K$ góc nhìn semantic độc lập về cùng slide.

**Lợi thế tính toán:** Chỉ tốn $K$ lần forward qua backbone (TITAN transformer), không cần recompute CNN patch features.

---

### Module B: DaPC Pseudo-label Correction (từ WeiContrast-DaPC)

DaPC so sánh confidence của **anchor model** $\theta_0$ (frozen source) và teacher để phát hiện domain shift và hiệu chỉnh nhãn giả. Cơ chế này hoạt động độc lập với pretraining strategy của source model — DaPC chỉ cần source model frozen và confidence của nó làm reference.

**Bước 1 — Chọn pseudo-label dựa trên anchor confidence:**

$$y^{teacher} = \begin{cases} \hat{y}' = \text{softmax}(\text{mlp}(\text{backbone}(B_i, \theta'))), & \text{nếu } \max\hat{y}_{anchor} \geq \tau_{ap} \quad \text{[IND]} \\ \tilde{y}' = \dfrac{1}{K}\sum_{k=1}^{K} \text{softmax}(\text{mlp}(\text{backbone}(B_i^{(k)}, \theta'))), & \text{otherwise} \quad \text{[OOD]} \end{cases}$$

trong đó $\hat{y}_{anchor} = \text{softmax}(\text{mlp}(\text{backbone}(B_i, \theta_0)))$.

**Bước 2 — Blend với anchor prediction:**

$$y^{corrected} = \begin{cases} \tilde{y}' & \text{nếu } \beta \cdot \max\tilde{y}' > \max\hat{y}_{anchor} \quad \text{[OOD nặng]} \\ \dfrac{1}{2}\!\left(\tilde{y}' + \hat{y}_{anchor}\right) & \text{otherwise} \quad \text{[IND hoặc OOD nhẹ]} \end{cases}$$

với $\beta \geq 1$.

**Hyperparameters:** $\tau_{ap} = 0.92$ (IND), $0.70$ (OOD); $\beta = 1.2$ (IND), $1.5$ (OOD).

---

### Module C: Hàm Loss Tổng hợp

#### Công thức tổng quát

$$\boxed{\mathcal{L}_{total} = \mathcal{L}_{PETAL} + \gamma_{class} \cdot \mathcal{L}_{class}}$$

#### Thành phần 1: $\mathcal{L}_{PETAL}$ — PETAL Bayesian Loss

$$\mathcal{L}_{PETAL} = \underbrace{-\,\text{spw} \cdot \log q(\theta_s)}_{\text{Regularizer: giữ backbone gần source}} + \underbrace{\bar{\lambda} \cdot H^{xe}(y^{corrected}, y_{student})}_{\text{Cross-entropy: thích ứng target domain}}$$

**Regularizer Bayesian** $\log q(\theta_s)$: Gaussian posterior xấp xỉ bằng SWAG-diagonal

$$\log q(\theta_s) = -\frac{1}{2} \sum_p \frac{(\theta_{s,p} - \mu_p)^2}{\sigma^2_p + \epsilon}$$

với $\mu_p,\, \sigma^2_p$ được tính từ `train_swag.py`. Tham số có $\sigma^2_p$ nhỏ (source chắc chắn) bị phạt nặng hơn khi thay đổi — đây là EWC tự nhiên từ Bayesian formulation.

**Ghi chú về tương tác SWAG–FIM:** $\sigma^2_p$ (SWAG) đo uncertainty của tham số theo source domain, còn $F_p$ (FIM) đo relevance của tham số với sample test hiện tại. Hai đại lượng này giải quyết hai câu hỏi khác nhau và bổ trợ lẫn nhau: SWAG bảo vệ stability, FIM đảm bảo adaptation efficiency.

**Cross-entropy** $H^{xe}$: student prediction phải khớp với pseudo-label đã hiệu chỉnh

$$H^{xe}(y^{corrected}, y_{student}) = -\sum_j y^{corrected}_j \cdot \log \text{softmax}(\text{logits}_{student})_j$$

**Ý nghĩa:** $\mathcal{L}_{PETAL}$ là CoTTA + Bayesian regularizer. Khi $\text{spw} = 0$, degrades thành CoTTA thuần túy.

#### Thành phần 2: $\mathcal{L}_{class}$ — Class Alignment với Temperature Scaling

$$\mathcal{L}_{class} = -\sum_j y^{corrected}_j \cdot \log \text{softmax}\!\left(\frac{\text{logits}_{student}}{\tau_c}\right)_j$$

Đây là soft cross-entropy **với temperature** $\tau_c = 0.07$ trên cùng logits của student. Gradient buộc backbone tạo $Z_i$ align với frozen class prototype weights.

**Tại sao cần $\mathcal{L}_{class}$ khi đã có $\mathcal{L}_{PETAL}$?**

$\mathcal{L}_{PETAL}$ là consistency loss: student đồng ý với teacher về phân phối xác suất. $\mathcal{L}_{class}$ là alignment loss: slide embedding $Z_i$ align trực tiếp với class prototypes trong embedding space. Khi $\tau_c = 1$, hai thành phần trùng công thức — nhưng $\tau_c = 0.07$ nhỏ làm logits sắc nét hơn, tạo gradient mạnh hơn để push $Z_i$ xa khỏi decision boundary. Điều này đặc biệt quan trọng với imbalanced classes (CESC, BRCA) vì minority class cần signal mạnh hơn để không bị dominated.

#### Bảng tóm tắt gradient signal

| Loss component | Buộc backbone làm gì | Giải quyết vấn đề gì |
|---|---|---|
| $-\,\text{spw} \cdot \log q(\theta_s)$ | Không drift xa $\mu_{SWAG}$ | Catastrophic forgetting |
| $\bar{\lambda} \cdot H^{xe}(y^{corrected}, y_{student})$ | Student đồng ý với teacher về phân phối | Thích ứng target domain |
| $\gamma_{class} \cdot \mathcal{L}_{class}$ | $Z_i$ align trực tiếp với class prototypes | Class-level alignment, class imbalance |

---

### Module D: FIM-based Parameter Restoration (từ PETAL)

Sau optimizer step, tính FIM để xác định tham số nào quan trọng với dữ liệu hiện tại:

$$F = \operatorname{Diag}\!\left(\nabla_\theta \mathcal{L}_{total}\right)\!\left(\nabla_\theta \mathcal{L}_{total}\right)^\top$$

Reset các tham số **không quan trọng** (FIM thấp) về source model $\theta_0$:

$$\gamma = \text{quantile}(F,\, \delta), \qquad m_p = \mathbb{1}[F_p < \gamma]$$

$$\theta_{t+1} = \mathbf{m} \odot \theta_0 + (\mathbf{1} - \mathbf{m}) \odot \theta_{t+1}$$

$\delta = 0.03$ nghĩa là 3% tham số có FIM thấp nhất (ít quan trọng nhất) bị reset về source sau mỗi step.

**Ghi chú:** FIM được tính trên $\mathcal{L}_{total}$ bao gồm cả regularizer Bayesian, do đó nó phản ánh importance của tham số đối với cả adaptation objective lẫn source knowledge. Các tham số thuộc nhóm $\sigma^2_p$ lớn (source không chắc) và $F_p$ lớn (test sample cần nhiều) sẽ được adapt mạnh nhất — cần theo dõi nhóm này khi pseudo-labels kém chất lượng ở OOD setting.

---

### Module E: Adaptive Learning Rate (inspired by NOTE)

**OOD score** cho mỗi slide — confidence gap giữa anchor và teacher:

$$\text{OOD\_score}(x) = 1 - \frac{\max \hat{y}_{anchor}}{\max \hat{y}_{teacher} + \epsilon}$$

Giá trị cao → anchor mất confidence so với teacher → sample có khả năng là OOD. Cơ chế này lấy cảm hứng từ nguyên lý per-instance OOD detection của NOTE (NeurIPS), được thích nghi cho Transformer backbone (TITAN dùng LayerNorm, không có Batch Normalization) bằng cách dùng prediction confidence gap thay cho IABN statistics.

**Adaptive learning rate:**

$$\eta_{eff} = \eta_{base} \cdot \sigma\!\left(\text{OOD\_score} - \tau_{OOD}\right), \quad \tau_{OOD} = 0.5$$

IND samples: $\eta_{eff}$ thấp → adaptation nhẹ → bảo tồn source knowledge. OOD samples: $\eta_{eff}$ cao → adaptation mạnh hơn.

## 4. Thuật toán Tổng hợp

```
Algorithm: MergeSlide-TTA (PETAL-WSI)

Input:
  - merge_final model: backbone với θ_s = θ_0 = θ̃_{1:T}
  - Teacher: θ' = θ_0 (khởi tạo, EMA của student)
  - Anchor: θ_0 (frozen hoàn toàn, không cập nhật)
  - mlp: Linear(768, n_classes) — frozen, init từ prompt prototypes
  - Posterior: μ_SWAG, σ²_SWAG từ train_swag.py
  - Task prompts: E^T ∈ R^{T×768} — frozen (chỉ dùng tại inference)

Hyperparameters (IND | OOD):
  - K=8,  r_patch=0.75 | 0.50    (bag augmentation)
  - τ_ap=0.92 | 0.70             (anchor confidence threshold)
  - β=1.2 | 1.5                  (DaPC sensitivity)
  - spw=1e-6,  lam_ce=1.0        (PETAL weights)
  - γ_class=1.0                  (L_class weight)
  - τ_c=0.07                     (L_class temperature)
  - δ=0.03                       (FIM quantile)
  - π=0.999                      (EMA alpha)
  - η_base=1e-4, τ_OOD=0.5       (adaptive lr)
  - τ_task=0.70                  (TCP routing confidence gate)

For each slide (features, coords):

  // === PHASE 1: Pseudo-label Generation ===
  1. idx = randperm(N)[:K_PATCHES]
     feat_std, cord_std = features[idx], coords[idx]

  2. ŷ_anchor = softmax(mlp(backbone(feat_std, cord_std, θ_0)))
     ŷ_teacher = softmax(mlp(backbone(feat_std, cord_std, θ')))

  3. OOD_score = 1 − max(ŷ_anchor) / (max(ŷ_teacher) + ε)
     η_eff = η_base · σ(OOD_score − τ_OOD)

  4. if max(ŷ_anchor) < τ_ap:   // anchor không tự tin → OOD → dùng aug-averaging
       ỹ' = (1/K) Σ_k softmax(mlp(backbone(B^(k), θ')))
     else:                        // anchor tự tin → IND → dùng direct teacher
       ỹ' = ŷ_teacher

  5. DaPC blend:
     if β · max(ỹ') > max(ŷ_anchor):
         y_corrected = ỹ'                        // OOD nặng: tin teacher
     else:
         y_corrected = 0.5 · (ỹ' + ŷ_anchor)    // IND/OOD nhẹ: blend

  // === PHASE 2: Student Forward ===
  6. Z_s = backbone(feat_std, cord_std, θ_s)
     logits_s = mlp(Z_s)
     y_student = softmax(logits_s)

  // === PHASE 3: Loss Computation ===
  7. log_q    = −0.5 · Σ_p (θ_{s,p} − μ_p)² / (σ²_p + ε)
     L_PETAL  = −spw · log_q + lam_ce · H_xe(y_corrected, y_student)
     L_class  = −Σ_j y_corrected_j · log softmax(logits_s / τ_c)_j
     L_total  = L_PETAL + γ_class · L_class

  // === PHASE 4: Student Update ===
  8. F = Diag(∇L_total)(∇L_total)^T      // tính FIM trước khi step
     scale optimizer lr theo η_eff
     optimizer.step()

  // === PHASE 5: Teacher EMA ===
  9. θ' ← π · θ' + (1 − π) · θ_s

  // === PHASE 6: FIM Restoration ===
  10. γ_q = quantile(F, δ)
      m_p = 1 if F_p < γ_q else 0
      θ_s ← m ⊙ θ_0 + (1 − m) ⊙ θ_s

  // === PHASE 7: Inference với TCP Confidence Gate ===
  11. Z_teacher = backbone(feat_std, cord_std, θ')
      tcp_scores = softmax(Z_teacher @ E^T.T)
      tcp_conf   = max(tcp_scores)

      if tcp_conf >= τ_task:
          t_hat  = argmax(tcp_scores)           // TCP routing đáng tin cậy
          logits = Z_teacher @ E^{C, t_hat}.T
      else:
          logits = mlp(Z_teacher)               // fallback: dùng toàn bộ class prototypes

      Return argmax(logits)
```

## 5. Phân tích Lý thuyết

### 5.1 Chống Catastrophic Forgetting

Ba cơ chế hoạt động song song ở ba temporal scale khác nhau:

**a) Regularizer Bayesian (parameter-level, mỗi gradient step):** $\log q(\theta_s)$ phạt drift khỏi posterior source. Tham số có $\sigma^2_p$ nhỏ (source chắc chắn về giá trị này) được bảo vệ mạnh hơn. Đây là EWC tự nhiên phát sinh từ Bayesian formulation của PETAL.

**b) FIM Restoration (parameter-level, sau mỗi step):** Reset tham số ít quan trọng về $\theta_0$ sau mỗi gradient step. Chỉ giữ lại thay đổi của tham số thực sự cần cho dữ liệu hiện tại — tránh tích lũy noise qua thời gian.

**c) Anchor model cố định (global, toàn bộ quá trình TTA):** $\theta_0$ không bao giờ cập nhật — đóng vai trò bộ nhớ dài hạn bất biến, được dùng trong DaPC để kéo pseudo-labels về phía source knowledge khi domain shift nhẹ.

### 5.2 Chống Tích tụ Lỗi

**a) DaPC:** Kéo pseudo-labels về phía anchor khi domain shift nhẹ → giảm error propagation. Khi shift mạnh, dùng aug-averaged teacher (đáng tin hơn single-pass prediction).

**b) Augmentation averaging:** Ensemble $K$ góc nhìn của cùng slide → pseudo-labels mịn hơn, ít bị ảnh hưởng bởi local noise từ patch sampling.

**c) Adaptive learning rate:** $\eta_{eff}$ thấp cho IND samples → không over-adapt, giảm tốc độ tích lũy lỗi trong luồng IND chiếm đa số.

### 5.3 Xử lý IND/OOD Mixed Stream

| Tình huống | Hành vi của framework |
|---|---|
| 100% IND | $\text{OOD\_score}$ thấp → $\eta_{eff}$ nhỏ → adaptation nhẹ; DaPC blend với anchor; TCP conf cao → routing chính xác |
| Mixed (IND + một phần OOD) | OOD samples có $\eta_{eff}$ cao hơn → adaptation chọn lọc theo từng sample |
| 100% OOD | $\text{OOD\_score}$ cao → adaptation mạnh; DaPC dùng aug-averaged teacher; TCP gate kiểm tra confidence trước khi routing |

### 5.4 TCP Routing Consistency

Khi backbone cập nhật, $Z_i$ dịch chuyển trong embedding space. TCP confidence gate ($\tau_{task} = 0.70$) đảm bảo: chỉ dùng TCP routing khi teacher model còn đủ confident vào task identity. Nếu không, fallback về toàn bộ class prototypes — tránh inference sai do TCP routing sai ở OOD nặng.

## 7. Metrics Đánh giá

### 7.1 Metrics chính

- **Balanced Accuracy (bACC):** Ưu tiên cho CESC, BRCA (imbalanced). $\text{bACC} = \dfrac{1}{C}\sum_c \text{Recall}_c$
- **ACC:** Overall accuracy sau adaptation

### 7.2 Metrics bổ sung

- **Per-class Recall và Precision:** Debug pseudo-label quality, đặc biệt cho imbalanced tasks
- **OOD score trung bình per fold:** Kiểm tra Module E hoạt động đúng — IND folds phải có score thấp hơn OOD folds
- **TCP confidence distribution:** Kiểm tra tần suất kích hoạt fallback inference ở OOD setting
- **Loss breakdown:** `loss_petal`, `loss_class` theo từng slide để debug tích lũy lỗi — cần monitor loss_petal tăng dần theo slide stream

### 7.3 Tránh ảnh hưởng bởi OOD val nhỏ

- Không chọn hyperparameters dựa trên OOD val từng fold (ESCA val min=1, TGCT val min=1)
- Grid search trên IND val (ổn định), giữ cố định cho tất cả folds
- Report mean ± std trên 10-fold cross-validation

## 9. Rủi ro và Hạn chế

**R1 — SWAG posterior quality:** Nếu `train_swag.py` chạy quá ít epochs, $\sigma^2_p$ không chính xác → regularizer không phân biệt tốt tham số quan trọng. Mitigation: chạy ít nhất 5 epochs, kiểm tra variance distribution.

**R2 — OOD val quá nhỏ:** Không validate $\tau_{ap}$ và $\tau_{OOD}$ reliably trên fold nhỏ. Mitigation: dùng cross-task validation (tuning trên BRCA/RCC, áp dụng cho ESCA/TGCT).

**R3 — $\mathcal{L}_{class}$ và $\mathcal{L}_{PETAL}$ overlap:** Khi $\tau_c = 1$, $\mathcal{L}_{class} \approx \mathcal{L}_{PETAL}$ CE term → double counting. Mitigation: giữ $\tau_c = 0.07$ (khác biệt đủ lớn), hoặc ablation D-1 kiểm tra đóng góp thực sự.

**R4 — Adaptive LR không ổn định:** Sigmoid sharp khi $\text{OOD\_score}$ gần $\tau_{OOD}$ có thể tạo gradient oscillation. Mitigation: EMA smooth OOD score qua một cửa sổ nhỏ (5–10 slides), hoặc dùng window average.

**R5 — TCP confidence gate chọn $\tau_{task}$ không phù hợp:** Nếu $\tau_{task}$ quá cao → fallback quá thường xuyên ở IND setting. Nếu quá thấp → không bảo vệ được khi OOD nặng. Mitigation: validate $\tau_{task}$ trên IND val (nơi TCP phải routing đúng gần 100%), chọn giá trị mà fallback rate < 5%.
